## 核心功能

1. **等时圈计算**：扇形 24 方向采样 + 二分搜索，真实路网可达范围；支持 5/10/15 分钟（300/600/900 秒）
2. **出行方式**：步行 / 骑行 / 公共交通（公交、地铁两行独立规划：避开地铁 vs 优先地铁）/ 驾车
3. **POI 设施分析**：医疗、教育、购物、养老、文体、餐饮、交通
4. **盲区检测**：两个口径——空间盲区（有坐标，地图红圈）/ 可达性盲区（按类别数量，报告展示），随出行方式变化
5. **真实路线显示**：中心到设施按出行方式切换真实路线，灰/高亮 toggle
6. **综合评分**：设施覆盖 35% + 可达性 25% + 出行适配 20% + 盲区 10% + 风水 10%
7. **风水评分**：七项加权（水系 20% 最高，地势/朝向/道路形态/敏感设施各 15%，绿化/人气各 10%）
8. **悬浮设施卡片**：步行/骑行/公交/地铁/驾车分列耗时（公交/地铁各自独立规划），按设施实际可达过滤，无直达明确提示

## 关键技术事实（2026-09-29 答疑确认）

- **等时圈公共交通 = 车程近似**：`isochrone_engine.py` `_travel_mode_for_speed` 对速度≥4m/s 走 driving 矩阵（百度矩阵 API 的 transit 端点 404 不可用，注释原话「公交用驾车API近似」）。所以「公共交通 15 分钟圈」实际是 15 分钟**车程**圈——圈边缘设施公交/地铁耗时超过 15 分钟是口径差的必然结果，不是计算错误。步行/骑行圈走对应真实 API 无此问题
- **悬浮卡耗时 = 门到门**：`plan.getDuration()` 是百度公交方案全程时长——两端步行进出站 + 换乘步行 + 估算等车时间 + 车内时间，不是纯坐车时间
- **CSS 架构**：main.tsx 导入顺序 index.css → three-column.css → report-styles.css → header-styles.css → comprehensive-report.css → mode-score-panel.css → score-overview.css，后者覆盖前者（改 CSS 要查全部 8 个文件，app-styles.css 未被导入）
- **BMap 坑**：`new BMap.Map(el)` 只在初始化取一次容器尺寸，容器变了要 `checkResize()`（已接 ResizeObserver）
